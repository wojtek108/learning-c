Function Pointers and Callbacks

So far every pointer you've met pointed at data. Here's the twist: functions live in memory too, and they have addresses. A function pointer stores the address of a function, so you can call it indirectly — and pass it around like a value. This powers callbacks, dispatch tables, and qsort().

Based on A Little Book of C, Chapter 28 (pp. 93–96)

Functions have addresses

When your program is loaded, its machine code lives in a region of memory called the text segment (also: code segment). Every function occupies a block of bytes there, and that block has a start address — just like every int on the stack or heap has an address.

Your memory map now has four regions:

RegionWhat lives thereDo you take its address?
text (code)Machine instructions — your functionsYes! That's a function pointer
staticGlobals, static variablesYes, like any variable
stackLocal variables, parametersYes (&x) — but beware lifetimes
heapmalloc'd memoryYes — the returned pointer itself

The bare name of a function is its address, in most contexts. This is exactly the same "decay" you already know from arrays:

int add(int a, int b) { return a + b; }

// these two are the same value — the address of add's code
add        // decays to a pointer, like an array name
&add       // explicit address — identical result for functions
The big idea A function pointer is just an address of code — the same idea as a data pointer, pointing into a different region of memory. Calling through it is an indirect call: the CPU jumps to whatever address the pointer holds. That indirection is what buys you runtime flexibility.

Declaring a function pointer — the syntax

The declaration mirrors how you use it. To call the pointed-to function you write (*fp)(2, 3) — dereference fp to get the function, then call it. So the declaration looks like that, with fp replacing the name:

int (*fp)(int, int);   // fp is a pointer to a function taking (int,int), returning int

Read it right-to-left: "fp is a pointer (*) to a function ((...)) taking two ints, returning int."

The parentheses are mandatory int *fp(int, int) — no parentheses — means something completely different: a function named fp that returns int *. The parens around *fp bind the * to the name, not to the return type.

Assigning and calling:

int (*fp)(int, int) = add;   // point at add's code

int result = fp(2, 3);        // call through the pointer — same as add(2, 3)
int also  = (*fp)(2, 3);     // explicit dereference — identical result

Both call forms work; fp(2, 3) is the idiomatic one.

The typedef shortcut

The full type name is verbose. Real code usually tames it with typedef:

typedef int (*binop)(int, int);   // "binop" = pointer to a 2-int function

binop f = add;   // now it reads like an ordinary type
int r = f(4, 2);

Tiny Code: the book's demo

Three arithmetic functions, one operate that takes a function pointer as a parameter:

#include <stdio.h>

int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }
int mul(int a, int b) { return a * b; }

void operate(int x, int y, int (*op)(int, int)) {
    printf("Result: %d\n", op(x, y));   // call through the pointer
}

int main(void) {
    int (*f)(int, int);      // declaration
    f = add;
    printf("Add via pointer: %d\n", f(5, 3));
    f = sub;
    printf("Subtract via pointer: %d\n", f(5, 3));

    printf("\nUsing callback function:\n");
    operate(4, 6, mul);   // pass the function itself as an argument
    return 0;
}

Output:

Add via pointer: 8
Subtract via pointer: 2

Using callback function:
Result: 24

Notice what happened: operate never mentions add, sub, or mul by name. It receives whatever function you hand it and calls it. That separation is the whole point of callbacks.

Arrays of function pointers — dispatch tables

Just like an array of int *, you can have an array of function pointers. The syntax reads "array of 3 pointers to functions":

int (*ops[3])(int, int) = {add, sub, mul};

for (int i = 0; i < 3; i++)
    printf("ops[%d](4, 2) = %d\n", i, ops[i](4, 2));

Output:

ops[0](4, 2) = 6
ops[1](4, 2) = 2
ops[2](4, 2) = 8
Dispatch tables replace chains of if/switch Instead of if (op == '+') ... else if (op == '-') ..., index into an array: ops[chosen](a, b). The index becomes the "choice", the array holds the behaviors. This is how interpreters, virtual machines, and command menus are built in C. The book calls these dispatch tables.

Callbacks

A callback is a function pointer you pass into another function, so that the callee can call back into your code at the right moment. The classic shape — a generic "do this to every element" loop:

#include <stdio.h>

void for_each(int *arr, int n, void (*callback)(int)) {
    for (int i = 0; i < n; i++)
        callback(arr[i]);   // "call back" into the caller's function
}

void print_square(int x) {
    printf("%d^2 = %d\n", x, x * x);
}

int main(void) {
    int nums[] = {1, 2, 3, 4, 5};
    for_each(nums, 5, print_square);   // pass the callback
    return 0;
}

Output:

1^2 = 1
2^2 = 4
3^2 = 9
4^2 = 16
5^2 = 25

The loop is written once, forever, and does nothing specific. The behavior — squaring, printing, summing — is supplied by whoever calls it. You can reuse for_each with a different callback and get entirely different behavior with zero changes to the loop.

Direction of control A callback is inversion of control: the generic function decides when your code runs; your code decides what it does. Event systems, signal handlers (signal(SIGINT, handler)), GUI button handlers — all this same pattern.

Why It Matters — qsort()

The standard library can't know how to order your types — so qsort() asks you for a comparison function:

int compare_desc(const void *a, const void *b) {
    return *(int *)b - *(int *)a;   // cast void* back, then subtract
}

int numbers[] = {5, 2, 9, 1, 7};
qsort(numbers, 5, sizeof(int), compare_desc);

qsort's signature: void qsort(void *base, size_t nmemb, size_t size, int (*compar)(const void *, const void *)). The const void * parameters are "pointers to anything" — you cast them back to your type inside the comparator. Negative/zero/positive return = a comes before / equal / after b.

Exercise 1 — three functions, one array

// func_ptr_array.c
#include <stdio.h>

int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }
int mul(int a, int b) { return a * b; }

int main(void) {
    int (*ops[3])(int, int) = {add, sub, mul};
    for (int i = 0; i < 3; i++)
        printf("%d\n", ops[i](10, 4));
    return 0;
}

Before you run it: what are the three printed values?

💡 Answer

Show 14, 6, 40 — add, sub, mul with (10, 4). Same code, three behaviors, selected by index.

Exercise 2 — calculate(a, b, op)

// calculate.c
#include <stdio.h>

typedef int (*binop)(int, int);

int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }
int mul(int a, int b) { return a * b; }

int calculate(int a, int b, char op) {
    binop table[] = {NULL, add, sub, mul};   // index 0 unused; map + - * to 1 2 3
    if (op == '+') return table[1](a, b);
    if (op == '-') return table[2](a, b);
    if (op == '*') return table[3](a, b);
    return 0;   // unknown operator
}

int main(void) {
    printf("%d\n", calculate(6, 2, '+'));
    printf("%d\n", calculate(6, 2, '-'));
    printf("%d\n", calculate(6, 2, '*'));
    return 0;
}
A cleaner variant Instead of three ifs, index the table directly with arithmetic: table[op - '+'] only works if + - * are adjacent in the character set — they are in ASCII. A lookup table keyed on the operator character is the "no branch" version of this exercise. Try writing that version yourself.

Exercise 4 — qsort descending

Sort an int array in descending order using qsort() from <stdlib.h>. Signature reminder: the comparator receives const void * and returns int (negative / zero / positive).

💡 Stuck? Smallest nudge

Show Swap the roles: return *(int *)b - *(int *)a; — subtracting a from b flips ascending into descending. That's all it takes.

Exercise 5 — a menu system

Print a menu ("1. Add 2. Sub 3. Mul 4. Quit"), read the user's choice, and dispatch with a function-pointer array instead of a switch. Loop until they choose Quit.

💡 Shape of the solution

Show binop table[] = {NULL, add, sub, mul}; then table[choice](a, b). Guard choice against 0 and out-of-range before indexing. The menu loop's break/return is the only control flow you need besides the index.

Check yourself

① What does int (*fp)(int, int) declare?

Show answer A pointer to a function taking two ints and returning int. The parentheses bind * to the name.

② What does int *fp(int, int) declare?

Show answer A function named fp that returns int * — not a function pointer at all. The * belongs to the return type.

③ What does the bare name add evaluate to when you assign f = add?

Show answer The address of the function's code in the text segment — the same value as &add. It decays to a pointer, like an array name.

④ In for_each(arr, n, print_square), who decides when and who decides what?

Show answer for_each decides when (once per element); print_square decides what (the behavior). That inversion of control is the essence of a callback.
